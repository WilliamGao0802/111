# 🎓 BGL 的 AI 学习

一个面向 **AI 学习者** 的在线学习平台：课程学习、知识点讲解、练习测评、AI 新闻、
讨论社区、文件共享、直播课堂、网课交易与管理员后台。

> 本项目的搭建严格遵循用户已有的 `streamlit-webapp-lifecycle` 技能（八阶段 + 八条铁律），
> 按「纵向切片 → 交付形态 → 迭代 → 功能扩展 → 发行 → 工程化 → 产品化合规 → 迁移」推进。

## 二、目录结构

```
bgl-ai-learning/
├── app.py                  # 入口：会话状态、登录门、侧边栏、路由分发、错误页、首启自举
├── launch.py               # 本地一键启动器（轮询端口就绪后再开浏览器）
├── serve.py / serve.sh     # ★ 云端部署入口（读 PORT、绑 0.0.0.0、适配反向代理）
├── version.py              # 唯一版本源 + 更新日志
├── core/                   # 业务逻辑层（★ 不 import streamlit）
│   ├── db.py               # SQLite 连接管理 + 全量 schema（43 张表）
│   ├── auth.py             # 注册/登录/加盐哈希/锁定/验证码/实名
│   ├── users.py            # 资料、关注粉丝、排行榜、用户管理
│   ├── news.py             # AI 新闻、Top5、分类标签、RSS、归档
│   ├── forum.py            # 讨论区：帖子、多级评论、@提及、草稿、举报
│   ├── files.py            # 文件区：上传、版本、预览、回收站、分享
│   ├── courses.py          # 课程/章节/课时、试看、进度、证书、评价、问答
│   ├── live.py             # 直播：预约、聊天、互动、连麦、回放、状态控制
│   ├── commerce.py         # 商品、购物车、优惠券、订单、支付、退款、结算提现
│   ├── knowledge.py        # 知识点讲解
│   ├── quiz.py             # 练习测评：组卷、判分、错题本、薄弱点
│   ├── admin.py            # 数据看板、审核队列、日志
│   ├── search.py           # 全站搜索
│   ├── notify.py           # 通知中心与私信
│   ├── ratelimit.py        # 接口限流防刷
│   ├── backup.py           # 备份导出 / 导入恢复
│   └── seed.py             # 演示数据
├── ui/                     # 展示层（每个模块一个页面）
├── tests/                  # 61 项测试（49 业务 + 12 界面 AppTest）
├── tools/                  # run_tests.py / release.py / deploy_sync.py / shot.js
├── 部署上线说明.md          # 发布到公网：文件清单、入口与依赖、方式选择、排障要点
├── data/                   # 运行时数据库（不入版本库）
└── uploads/                # 上传文件（不入版本库）
```

**分层铁律**：`app.py` 只做 UI 与路由，全部业务逻辑在 `core/`，且 `core/` 不允许
`import streamlit`。这样界面层可以整体替换，业务规则仍可离线测试。

## 三、运行测试

```bash
python tools/run_tests.py
# 或
python -m unittest discover -s tests -v
```

当前：**60 项测试全部通过**。

- `tests/test_core.py`：业务规则（密码校验、账号锁定、上限、版本/配额、支付签名、
  退款规则、实名门槛、限流、备份往返 …）
- `tests/test_app.py`：用 Streamlit 官方 `AppTest` 真实渲染每个页面，
  外加登录失败、课程详情双分支、测评组卷、全局搜索、主题切换等交互用例。

> 为什么不用无头浏览器截图做验证：Streamlit 是 SPA，`--dump-dom` 只能拿到骨架，
> 无法反映真实渲染结果。官方 `AppTest` 才是可靠手段。

## 四、发布流程

```bash
python tools/release.py 1.1.0 "本次更新说明"        # 完整发布
```

## 五、部署上线（发给别人用）

本地版绑 `127.0.0.1`、只给自己看；要让别人从公网访问，用**部署入口**：

```bash
python tools/deploy_sync.py                    # 生成干净部署包 dist_deploy/（约 0.7 MB）
PORT=8501 python serve.py                      # 或 bash serve.sh
```

| 要点 | 说明 |
|---|---|
| 端口 | 平台通过环境变量 **`PORT`** 注入，`serve.py` 负责读取；绑 `0.0.0.0` |
| 反向代理 | `serve.py` 已关 CORS / XSRF 校验，否则平台域名下 WebSocket 握手会失败 |
| 首启自举 | `app.py::ensure_ready()` 自动建 43 张表并按需灌演示数据（幂等，空目录首启即可用） |
| 数据持久化 | 设 `BGL_DB_PATH=/data/bgl.db` 指向挂载卷，重启不丢 |
| 依赖 | `requirements.txt` 只有 3 个（streamlit / pandas / altair），`core/` 是纯标准库 |
| 上传清单 | `dist_deploy/` 内容；**不要上传** `.venv/`（357MB）、`data/backups/`、`uploads/`、`tests/` |

**完整的部署方式选择（平台一键发布 / Streamlit Cloud / 自建 VPS）、启动命令速查与故障排查表见
[`部署上线说明.md`](部署上线说明.md)。**

## 六、⚠️ 演示模式说明（重要）

为了保证开箱即用、零外部依赖，以下能力为**本地模拟实现**，界面与文案均已明确标注：

| 能力 | 当前实现 | 生产替换方式 |
|---|---|---|
| 短信验证码 | 页面上直接显示 6 位码 | 替换 `auth.send_code()` 内的下发逻辑为短信服务商 SDK |
| 邮件验证码 | 页面上直接显示 | 同上，改用邮件服务 |
| 在线支付 | 本地模拟回调 + 签名二次校验 | 接入微信支付 / 支付宝 / Stripe 的统一下单与异步通知 |
| 直播推流/播放 | 占位播放器 + RTMP 演示地址 | 接入腾讯云直播 / 阿里云直播 / OBS-RTMP 拉流 |
| 视频点播 | 演示播放器 | 接入腾讯云 VOD / 对象存储直链 |
| 第三方登录 | 预留入口 | 接入微信 / GitHub / Google OAuth |
| 数据库 | SQLite（单文件） | `core/db.py` 换成 PostgreSQL 实现即可，上层无需改动 |

这些正是需求书第七章「预留接口，未来可接入数据库（PostgreSQL）、对象存储（S3）、
真实短信/邮件/支付服务」所要求的形态。

## 七、许可与合规

- 站内已内置《用户协议》《隐私政策》《购课协议》《退款政策》提示与勾选同意流程。
